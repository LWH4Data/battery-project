## 2. 아웃풋에 담고 싶은 내용

### 2.1 이야기, 그래프, 해석의 연결

전달하려는 주장에 맞는 그래프를 사용하고, 그래프에서 실제로 확인되는 내용을 해석한다. 그래프를 나열하는 형태로 보고서를 구성하지 않는다.

각 분석은 다음 흐름을 갖춘다.

> 분석 질문 → 핵심 관찰과 그래프 → 해석 → 시사점 → 피처·전처리·모델 전략과의 연결

- 그래프의 축, 단위, 배치, 분석 대상과 관측 범위를 명시한다.
- 수치나 비교 근거로 핵심 관찰을 뒷받침한다.
- 관찰된 연관성과 인과적 설명을 구분한다.
- 아직 확인하지 않은 원인을 사실처럼 쓰지 않는다.
- 해석의 한계와 추가 확인이 필요한 부분을 기록한다.

### 2.2 ML 모델을 선정한 이유

- 후보 모델은 EDA에서 확인한 데이터 특성과 연결해서 제시한다.
- 모델 이름을 나열하는 데 그치지 않고, 기대하는 장점·필요한 전처리·한계를 설명한다.
- 피처의 유형, 관계의 선형성·비선형성, 표본 수, 이상치, 해석 가능성 등을 근거로 삼는다.
- 특정 모델이 좋다는 일반론을 이 데이터의 성능 결과로 대신하지 않는다.

사용자가 제시한 모델 설명 예시는 다음과 같이 보존한다. 아래는 채택 모델 목록이 아니다.

| 예시 | 작성 시 정확하게 설명할 내용 |
| --- | --- |
| CatBoost | 범주형 변수를 내부적으로 처리할 수 있다는 특성을 선정 이유로 검토할 수 있다. 모든 범주형 처리가 단순 One-hot 인코딩이라는 뜻은 아니다. 실제 피처에 범주형 변수가 있는지와 내부 처리 방식을 확인한다. |
| SVM | 커널을 통한 비선형 관계 표현을 검토할 수 있다. 선형 커널도 있으므로, 선형 관계에서는 SVM이 항상 불리하다는 규칙으로 사용하지 않는다. 커널·스케일링·규제와 데이터 특성을 함께 설명한다. |
| OLS | 선형 관계와 해석 가능성 등을 검토한다. OLS를 선택했다는 이유만으로 특정 피처가 자동으로 정당화되는 것은 아니다. 피처의 타당성과 추론에 필요한 가정·공선성 등을 별도로 확인한다. |

이 표는 예시의 기술적 의미를 명확하게 하기 위한 보충 설명이며, 새로운 과제 요구사항을 추가하지 않는다. CatBoost와 SVM 관련 참고: [CatBoost 공식 문서](https://catboost.ai/docs/en/features/categorical-features), [scikit-learn SVC 공식 문서](https://scikit-learn.org/stable/modules/generated/sklearn.svm.SVC.html).

### 2.3 Feature 선정과 파생변수의 타당성

- 각 피처를 왜 선정했는지 객관적인 근거를 남긴다.
- EDA에서 확인한 관계, 배터리 관련 설명, 참고 자료, 모델의 가정·특성 등을 근거로 사용한다.
- 파생변수는 정의, 계산식, 관측 사이클 범위, 선정 이유를 기록한다.
- 원변수와 파생변수 사이의 중복 정보와 다중공선성을 확인한다.
- 파생변수가 공선성을 반드시 일으킨다고 단정하지 않고 실제 관계를 확인한다.
- 피처 선택의 기준은 모델 개발 데이터 안에서 정하고 적용한다.

### 2.4 가설 검정 — 선택 사항

EDA의 세부 질문 중 적합한 부분에는 가설 검정을 사용할 수 있다. 사용한다면 가설, 비교 단위, 검정 방법과 가정, 효과의 크기와 불확실성을 함께 설명한다. 같은 셀의 여러 사이클을 서로 독립적인 배터리 표본으로 취급하지 않도록 주의한다. 질문 3은 Batch 2 내부의 장수명(>1,000) 3셀/단수명(<500) 28셀 log10(ΔQ 분산) 비교로 확정했다. 주 검정은 양측 Welch t-test, 보완은 평균 차이의 정확 순열검정, 유의수준은 0.05다. EDA 후 선택한 탐색적 비교와 소표본·교란 한계를 명시한다.

### 2.5 Optuna — 검토 항목

하이퍼파라미터 최적화 도구로 Optuna를 검토한다. 사용 여부는 아직 확정하지 않았다. 사용한다면 탐색 공간, 목적 지표, CV 방식, seed, trial 수 또는 실행 예산, 최적 설정을 기록한다. 최적화에는 Batch 1의 개발용 CV만 사용한다.

## 3. 진행 중 Remind할 원칙

### 3.1 재현성 및 생산성 (Productivity)

- 데이터 분할, 모델 초기화, 샘플링 등 무작위성이 있는 단계에 `random_state` 또는 해당 도구의 seed를 고정한다.
- seed 고정과 함께 라이브러리·환경·데이터 정보를 기록한다. seed만으로 모든 환경에서 동일 결과가 보장된다고 주장하지 않는다.
- 환경 구성 시 Python 및 패키지 버전을 기록한다.
- 데이터 확보·변환 시 원본 파일 식별 정보, 데이터 스냅샷 또는 해시, 변환·제외 규칙을 기록한다.
- 실험 실행 시 코드 버전, 실험 설정, 분할 ID, 피처·타깃 정의, 실행 시각을 남긴다.
- 제출 시 결과를 만든 환경과 실험 버전을 연결한다.

### 3.2 Data Leakage

- 모델 개발용 train/validation/test 역할과 분할을 스케일링·인코딩·샘플링 등 학습형 전처리보다 먼저 정한다.
- 스케일러·인코더·결측값 처리 등 데이터에서 기준을 학습하는 단계는 train에서만 `fit`하고, 나머지에는 `transform`을 적용한다.
- `fit`: 데이터에서 변환 기준값을 계산해 저장하는 단계.
- `transform`: 저장된 기준값으로 데이터를 변환하는 단계.
- CV에서는 각 fold의 train 부분에서 전처리·피처 선택·샘플링을 학습하도록 파이프라인을 구성한다.
- Target에서 파생되거나 예측 시점 이후의 정보를 포함하는 입력 피처를 점검한다.
- 초기 수명 예측 입력은 정한 관측 범위 안에서만 계산한다. 전체 열화 곡선이나 전체 수명에서 얻은 Knee point는 EDA용 분석과 구분한다.

분할 원칙은 예측 단위에 맞게 적용한다.

- 시간에 따른 미래 값을 예측하는 시계열 문제는 시간 순서를 유지하고 무작위 시간 분할을 피한다.
- 셀 하나당 한 행으로 초기 정보에서 최종 수명을 예측하는 문제라면 셀 단위 독립성을 우선 확인한다. 원본이 시계열이라는 이유만으로 모든 셀 단위 무작위 분할을 금지하지 않는다.
- 같은 셀의 정보가 서로 다른 분할로 들어가지 않게 한다.
- 동일 충전 프로토콜 그룹을 분리하려는 평가 목적이라면 Hold-out과 CV 양쪽에 그룹 기준을 적용한다. Hold-out이라는 이름만으로 프로토콜 분리가 보장되지는 않는다.

그룹 및 시간 분할 참고: [scikit-learn 교차검증 공식 문서](https://scikit-learn.org/stable/modules/cross_validation.html).

### 3.3 Honest Evaluation

- Test는 모델 선택·최적화에 사용하지 않고, 선택한 모델의 최종 성능 평가에 사용한다.
- Test 결과를 보고 재튜닝해서 같은 Test의 결과를 독립적인 최종 평가처럼 제시하지 않는다.
- 과제 지침은 Batch 1·2·3 EDA를 요구한다. 이 배치 비교 EDA와 Batch 1에서 수행하는 모델 선택·튜닝을 구분하고, Batch 2·3 EDA를 수행했다는 사실을 보고서에 밝힌다.
- 모델 전략에 테스트 배치의 정보를 참고했다면 완전히 미관찰한 테스트라고 주장하지 않는다.
- 평가 데이터는 평가 목적에 맞는 실제 분포를 유지한다. 불균형 분류라면 Test의 클래스 분포를 임의로 균형화하지 않는다.
- Accuracy 하나만으로 판단하지 않고 목적에 맞는 지표를 함께 사용한다.
- Live Test는 실제 운영 데이터가 있는 경우의 평가 원칙이다. 현재 과제에서 수행 여부는 미정이다.

### 3.4 Generalization

- 과적합을 점검하고 개발·검증·테스트 성능 차이를 해석한다.
- 클래스 불균형에서 샘플링·가중치 조정은 선택지이며 무조건 적용하는 해결책으로 취급하지 않는다.
- 불균형 처리 방법은 개발 데이터에서 선택하고, 분포를 유지한 최종 Test에서 효과를 확인한다. Test 결과로 다시 방법을 선택하지 않는다.
- 학습 데이터가 평가·운영 대상을 대표하는지 확인한다.
- 운영 시에는 입력 분포와 대표성이 바뀌는지 정기적으로 점검한다.

### 3.5 Monitoring — 운영 시 참고

- Model Drift: 운영 중 예측 성능 저하를 추적한다.
- Data Drift: 입력 분포 변화를 감시한다. 성능 저하에 앞서 관찰될 수 있지만, 분포 변화만으로 성능 저하를 단정하지 않는다.
- Retraining: 재학습 주기와 실행 조건을 사전에 정의한다.

## 5. DAY 2 연결 기준 — 이전 과제 조건 요약

- Batch 1 내부 CV로 후보 모델을 비교·튜닝한다.
- Batch 1 Hold-out은 별도 검증으로 사용한다. 최종 학습 범위와 재학습 방식은 추후 명시한다.
- 선택한 모델을 Batch 2에서 최종 평가하고, Batch 3 평가는 선택 사항으로 진행한다.
- 성능 보고 구분: Train (Batch 1 CV), Valid (Batch 1 Hold-out), Test (Batch 2), 각 Gap, 선택적으로 Test (Batch 3).
- Train (Batch 1 CV)는 CV 평균 성능이며 학습 표본에 다시 예측한 적합 성능과 구분한다.
- 회귀 주 지표는 MAPE, 분류 지표는 F1-Score와 Accuracy다. 이전 안내의 분류 지표 행에 반복된 `Regression` 표기는 문맥에 따라 분류로 정리했다.
- 과제 제공 비교 Target: 회귀 MAPE 9.1%, 분류 오류율 4.9% / Accuracy 95.1%.
- 위 값은 과제에서 제공된 비교 기준으로 기록한다. 예측 시점·타깃 정의·분할·제외 셀 등의 차이를 설명하고, 원논문의 실험을 정확히 재현했다고 자동으로 주장하지 않는다.
- Gap의 차감 방향과 단위는 추후 확정한다. MAPE는 낮을수록, F1·Accuracy는 높을수록 좋은 지표라는 점을 반영해 부호를 설명한다.
- Batch 3에는 수명 분포, 곡선 정렬, 품질 문제가 있을 수 있다는 과제 안내를 검증 대상으로 기록한다. 원인과 제외 여부를 실제 데이터 확인 없이 확정하지 않는다.

- 실제 학습: OLS LinearRegression, `delta_q_log10var` 하나, 원본 Cycle Life. 개발 CV MAPE 7.2398%, MAE 60.14사이클, RMSE 72.26사이클.
- 하이퍼파라미터 탐색 미실행. Grid Search는 제안 단계, Optuna의 채택·범위·예산도 미확정이다.
- Hold-out·Batch 2·3 미평가, 후보 비교·최종 선택·재학습 범위·Gap 정의 미확정 상태를 유지한다.
- README에 정리한 개발 오류는 **저장된 OOF 예측**에서 계산했다. 문서 작성으로 새로운 학습·튜닝·Test 평가를 수행하지 않는다.
- 사용자 후속 요청: 프로젝트를 Public GitHub로 푸시하도록 명시했다. 로컬 Git을 초기화하고 공개 저장소 [LWH4Data/battery-project](https://github.com/LWH4Data/battery-project)를 생성했다. 과제 제출처에 링크를 제출하는 작업은 별도다. 모델 개발·최종 평가의 미완료 상태는 유지한다.
